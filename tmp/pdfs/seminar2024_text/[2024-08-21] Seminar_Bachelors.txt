ROSBAG
23
• Filepath: The path to the rosbag file - A rosbag file is a file format used in ROS to record 
sensor data, messages, and topics.
Messages: In ROS, a message is a data packet with a specific structure.
• Sensor Data Messages: Data collected by various sensors, including image data, distance 
measurements, acceleration values, etc.
• Status Messages: Information such as the robot's current location, speed, battery status, etc.
• Command Messages: Specific commands, such as movement commands for the robot or commands 
to open/close a gripper.
• StartTime, EndTime: The timestamps of the first and last recorded messages, represented in 
UNIX time format.
• NumMessages: The total number of messages contained in the rosbag file.
• AvailableTopics: The topics recorded in the rosbag file - 5 topics, 3 attributes.
• Imu, Lidar, Odometry, Radar, Camera: Five types of sensors.
• AvailableFrames: The frames available in the rosbag - indicated as "0x1 cell," meaning the 
rosbag file does not contain frame information.
• MessageList: A label where information about all messages is stored.


IMU
• MessageType: 'sensor_msgs/Imu'
This indicates that the message type is related to sensor data, specifically an IMU message, which is used to convey information about the 
inertial measurement unit's data in ROS.
• Header: 1x1 Header
This field contains metadata about the message, such as the timestamp and frame ID. It's represented as a 1x1 structure, meaning it likely 
contains a single instance of a Header.
• Orientation: 1x1 Quaternion - X : -0.0068, Y : -0.0045, Z : 0.1399, W : 0.9901
This field stores the orientation of the IMU as a quaternion, which is a common way to represent rotations in three-dimensional space. The 
1x1 indicates a single quaternion instance.
• AngularVelocity: 1x1 Vector3 – X : 0.0019, Y : 0.0016, Z : -0.0011
This field holds the angular velocity data of the IMU in three dimensions, using a vector of three components (x, y, z). It is slowly rotating 
clockwise around the X and Y axes (0.0019, 0.0016) and counterclockwise around the Z axis (-0.0011).
• LinearAcceleration: 1x1 Vector3 - X : -0.0790, Y : 0.1780, Z : -9.7918
This field contains the linear acceleration data of the IMU in three dimensions, similar to the angular velocity, It is primarily moving in the Y-
axis direction, with very small accelerations in the X and Y axes, indicating that the robot is moving in these directions with little change. The 
large negative acceleration in the Z-axis suggests that the robot is accelerating downward due to gravity.
• OrientationCovariance: [2.7921e-05;0;0;0;2.7974e-05;0;0;0;0.0030]
This is a 3x3 matrix (flattened into a single row) that represents the covariance of the orientation data. The values provided indicate the 
uncertainty associated with each component of the orientation.
• AngularVelocityCovariance: [0;0;0;0;0;0;0;0;0]
This is a 3x3 covariance matrix for the angular velocity data, where all values are zero, suggesting no uncertainty (or it hasn't been 
measured).
• LinearAccelerationCovariance: [0;0;0;0;0;0;0;0;0]
Similar to the angular velocity covariance. 24
Quaternion: A mathematical method for representing 
rotation in 3D space, which can be converted into Euler 
angles, rotation matrices, and other forms.
q = w + xi + yj + zk:
w represents the scalar part (real part).
x, y, z represent the vector part (imaginary part).

ODOMETRY
• Estimating "relative position" to determine how far the robot is from its starting point: The distance is 
measured using encoders attached to the motors (wheels). By analyzing the encoder values and the 
distance traveled, the robot's position is estimated using the wheel angles and the distance covered.
• MessageType: 'nav_msgs/Odometry'
This indicates that the message is of type Odometry, which is used in ROS to describe the position and 
velocity of a robot in a given frame.
• Header: 1x1 Header
This field contains metadata about the message, such as the timestamp and frame ID. The 1x1 indicates it is 
a single instance of a Header structure.
• Pose: 1x1 PoseWithCovariance
This field holds the position and orientation of the robot. The robot's position (3D coordinates) and 
orientation (in Quaternion format) are included, along with a covariance matrix that represents the 
uncertainties associated with these values.
• Twist: 1x1 TwistWithCovariance
It includes linear velocity and angular velocity, along with a covariance matrix that represents the 
uncertainties associated with these values. 
Since the values for all axes of both linear velocity and angular velocity are 0, it indicates that the robot is in 
a stationary state. Since all values in the covariance matrix are 0, it indicates that there is no uncertainty, or 
that uncertainty is not being considered.
• ChildFrameId: 'base_link'
This is the ID of the child coordinate frame associated with the odometry data, often referred to as 
base_link. It represents the frame of reference for the robot's body.

RADAR
• PreserveStructureOnRead: 0
This indicates whether the structure should be preserved when reading the data. A value of 0 means that the structure is not preserved.
• MessageType: 'sensor_msgs/PointCloud2'
This specifies that the message type is PointCloud2, which is commonly used in ROS to represent 3D point cloud data, such as that collected from LIDAR 
or radar sensors.
• Header: 1x1 Header
Contains metadata about the message, such as the timestamp and frame ID. The 1x1 indicates it is a single instance of a Heade r structure.
• Fields: 5x1 PointField
Represents the fields of the point cloud data, where each field corresponds to a specific attribute of the point cloud (e.g., x, y, z coordinates, intensity). 
The 5x1 indicates that there are five fields in the point cloud.
• Height: 1
Indicates the height of the point cloud data. A value of 1 typically means that the point cloud is organized as a single row of points, often referred to as 
a "unorganized" point cloud.
• Width: 2
Indicates the width of the point cloud data, which is the number of points in each row.
• IsBigendian: 0
Specifies the endianness of the data. A value of 0 indicates that the data is in little-endian format.
• PointStep: 32
The length of a point in bytes, indicating the size of each point in the point cloud.
• RowStep: 64
The length of a row in bytes, which is the total number of bytes in each row of the point cloud.
• Data: 64x1 uint8
The actual point cloud data, represented as an array of unsigned 8-bit integers (uint8). The 64x1 suggests there are 64 bytes of data in total.
• IsDense: 1
Indicates whether the point cloud is dense. A value of 1 means that all points in the point cloud are valid, with no invalid (NaN) points. 26

RADAR - FIELDS
• The point cloud data consists of five fields: x, y, z, intensity, and velocity.
• Offset: Indicates the position, in bytes, where this field starts within each point's data. In this case, it is set 
to 0, meaning the X coordinate data starts from the first byte of the point cloud data.
• Datatype: Specifies the data type in which the point cloud data is stored. The value 7 represents the 
FLOAT32 type, so the X coordinate value is stored in a 32-bit floating-point format.
• Count: Indicates the number of elements that make up this field. Here, it is set to 1, meaning there is one 
X coordinate value for each point.
27
• The X coordinate is stored in a 32-bit floating-point format (FLOAT32), starting at a 0 -byte offset within each point's 
data structure. The image provides information about the x coordinate field in 3D point cloud data. 
• The Y coordinate of the 3D point cloud data is stored in a 32 -bit floating-point format, and this value is located at an 
offset of 4 bytes after the start of each point in the array.
• The Z coordinate data is stored at an 8 -byte offset position in the array, following the X and Y coordinate data. This 
field defines the Z coordinate of each point in the 3D point cloud data and is stored in a 32 -bit floating-point format.
• The intensity data is stored at a 16 -byte offset position in the array, following the X, Y, and Z coordinate data. This 
field defines the intensity of each point in the 3D point cloud data and is stored in a 32 -bit floating-point format.
• The velocity data is stored at a 20 -byte offset position in the array, following the X, Y, Z coordinate, and intensity 
data. This field defines the velocity of each point in the 3D point cloud data and is stored in a 32 -bit floating-point 
format.
