# v3.1: 관측 품질이 정보 선택에 도달하는 공유 R-GAT

2026-10-24 사용자 요청에 따라 **모델 자체를 변경**했다. 목표는 일반 PPO보다 미지 조건에서 잘 착륙하고, 관측 잡음·누락과 UGV 급가속에 더 잘 대응하는 것이다. 이는 검증할 목표이며 아직 달성한 성능으로 주장하지 않는다.

**개발 완료:** 15개 모델·9,000개 에피소드의 [결과 분석](MINIMAL_V31_RESULTS_20261024_KO.md)에서 OOD 착륙률은 PPO 77.93%, TOSM 59.07%, Shuffled 44.87%였다. 품질→두 번째 홉 경로는 학습된 모델에서도 확인했지만, PPO 대비 성능 개선은 입증하지 못했다. 아래 내용은 변경의 설계 가설과 실행 전 검증 기록이다.

## 1. 확인한 구조적 한계

v3의 한 홉 점수는 관계별로

$$s_{j\to i}=\operatorname{LeakyReLU}(a_s^TW_rh_j+a_d^TW_rh_i+\beta_r)$$

이다. 두 운동 노드는 같은 관계 $r$를 쓰므로, 이 둘의 점수 순위는 도착 노드의 상태에 따라 뒤집힐 수 없다. 이 제한과 비선형 연산 순서를 바꿔 동적 attention을 만드는 원리는 [Brody 등의 GATv2 논문](https://arxiv.org/abs/2105.14491)에 설명되어 있다. 여기서는 관계별 가중치와 공유 사영을 사용하는 제한된 변형이며 논문의 모든 표현력 정리를 그대로 주장하지 않는다.

별도로, 한 홉에서는 ObservationQuality가 RelativeState의 입력에 아직 들어 있지 않다. 품질 값만 바꿔도 운동 간선들의 점수는 그대로라서

$$\frac{\alpha_{Target\to Relative}}{\alpha_{Own\to Relative}}=\exp(s_{Target\to Relative}-s_{Own\to Relative})$$

가 변하지 않는다. 품질 메시지는 행동이나 모든 운동 메시지의 공통 크기를 바꿀 수 있지만, 두 운동 증거 사이의 상대적인 선택에는 쓰이지 못한다. **이것이 기존 모델이 품질에 전혀 반응하지 못한다는 뜻은 아니다.** 후단 MLP의 보상 가능성도 있으므로 전체 성능 부진의 유일한 원인으로 단정하지 않는다.

### 학습 모델에서 확인한 값

개발 시드 251–255의 그래프 모델 10개를 읽었다. validation 시드 2001–2004의 정책 독립 기준 궤적에서 관측 44개를 고정하고, 품질 두 성분만 fresh=[1,0], stale=[0,0.6]으로 바꿨다. 실제 센서 궤적 비교가 아니라 입력 경로를 격리한 구조 진단이다.

- 두 운동 간선의 log attention ratio 변화 최대: **2.78×10⁻¹⁶**.
- 정규화 행동 변화의 평균 노름은 모델별 약 **0.058–0.160**. 따라서 품질 입력이 무시된 것이 아니라 선택 경로에 제한이 있었다.
- 학습·체크포인트 선택·OOD 결과 탐색은 하지 않았다.
- 근거: `results/minimal_v31/development/diagnose_v3.m`, `v3_routing_diagnosis.mat`, `.log`.

## 2. 수정한 모델

노드·입력·간선·readout은 그대로 둔다. **같은 가중치를 두 번 사용**해 집계하고, attention에서 출발·도착 특징을 결합한 뒤 비선형 함수를 적용한다.

$$h_i^0=\tanh(PX_i+b_P),$$
$$u_e^\ell=W_rh_j^{\ell-1}+W_rh_i^{\ell-1}+b_a,$$
$$s_e^\ell=a^T\operatorname{LeakyReLU}_{0.2}(u_e^\ell)+\beta_r,\qquad
\alpha_e^\ell=\operatorname{softmax}_{e':dst(e')=i}(s_{e'}^\ell),$$
$$h_i^\ell=\tanh\left(W_0h_i^{\ell-1}+\sum_{e:dst(e)=i}\alpha_e^\ell W_rh_j^{\ell-1}+b\right),
\quad \ell=1,2,\qquad g=h_{RelativeState}^2.$$

첫 집계에서 품질·운동·상대 상태를 결합한다. 두 번째 집계에서는 이 문맥을 query로 사용해 이웃의 상대적 반영 정도를 학습할 수 있다. 두 집계의 $W_r,W_0,a,b_a,\beta,b$는 같은 파라미터다. Actor와 Critic 사이에는 공유하지 않는다.

출발·도착 사영도 같은 $W_r$를 사용한다(GATv2의 share_weights에 해당). 관계별 메시지와 root+self 구조는 유지하며 품질 임계값·고정 신뢰도 가중치·필터·안전 가드를 넣지 않는다. 이 변경은 의미 그래프를 통한 학습 가능한 조건부 정보 선택이다. 기존 한 홉의 단순히 작은 출력이나 강제 평활화를 목표로 하지 않는다.

| 항목 | v3 | v3.1 |
|---|---|---|
| 노드 / 간선 / 입력 | 4 / 7 / 같은 10차원 | 동일 |
| 집계 횟수 | 1 | **2, 가중치 공유** |
| 점수 비선형 순서 | 선형 점수 → LeakyReLU | **공동 특징 → LeakyReLU → 선형 점수** |
| attention 파라미터 | 출발 8 + 도착 8 + 관계 3 | **점수 8 + 공동 bias 8 + 관계 bias 3** |
| 인코더 / 전체 파라미터 | 371 / 1,419 | **371 / 1,419** |
| PPO MLP·손실·학습 설정 | 기존 값 | 동일 |

계산량은 두 번 집계하므로 증가한다. 파라미터 수가 같다고 실행 비용까지 같다고 주장하지 않는다. 두 변경의 개별 성능 기여는 분리 실험하지 않았으므로 v3.1 묶음의 결과로만 해석한다.

## 3. 기대 효과와 실패 가능성

- 품질 문맥에 따라 운동 증거를 다르게 반영할 수 있어 누락·잡음과 실제 운동 변화의 구분을 학습할 여지가 생긴다.
- 같은 관계 변환을 두 집계와 여러 상태에서 공유해 적은 파라미터로 조건부 조합을 학습한다.
- 강한 신호를 무조건 줄이지 않으므로 급가속 추종을 유지하면서 불필요한 명령 변화를 줄이는 것이 목표다.

**이는 설계 가설이다.** 품질 입력에는 실제 추정 오차나 센서 잡음 분산의 정답이 없다. 신선하지만 잘못된 관측을 완전히 구분할 수 없으며, 두 번 집계가 과도한 혼합이나 최적화 지연을 만들 수도 있다. 현재 급변 시험은 물리적으로 연속적인 UGV 가속 크기 변화이고 순간이동·임의 방향 반전을 검증하지 않는다.

## 4. 공정한 학습과 일반화 검증

- TOSM과 Shuffled에 **같은 새 인코더**를 적용한다. Shuffled는 기존과 같이 어떤 두 증거가 관계 변환을 공유하는지만 바꾼다. 초기 파라미터는 짝 시드에서 동일하다.
- 모든 방법의 2D 물리·센서·관측·reward_v5·행동·종료·PPO 손실·탐색·예산·검증을 유지한다. PPO 경로는 동일 시드 초기 가중치와 출력의 비트 일치로 검사한다.
- 새 개발 학습 시드 **271–275**, 확인 **281–290**. PPO도 새 시드에서 학습한다. 이전 결과·확인 예약 261–270은 섞지 않는다.
- 기존에 고정한 generalization_v1 조건과 주 비교를 유지한다. 가속 1.0–1.5 m/s², 누락 1.2–2.0초, 잡음 ×2, 각 요인의 ID 참조를 함께 평가한다. 조건을 새 모델 결과에 맞춰 바꾸지 않는다.
- 주 지표는 세 OOD 요인의 동등 가중 착륙률. TOSM−Shuffled와 TOSM−PPO의 짝 차이를 두 주 비교로 보고한다. 위험 접촉·추종·최악 조건·ID 대비 감소를 함께 공개한다.
- AUC·명령 변화와 S1–S3는 보조 결과다. 일반화와 잡음 강인성은 해당 요인에서의 성능과 안전·추종을 함께 충족하는 범위에서만 주장한다.

## 5. 버전과 실행

- 특징 `tosm4_v1` 유지, 인코더 **rgat_minimal_v2**, 학습 서명 **minimal-relational-v3.1**.
- `landing2d.minimal.config()`가 새 버전이다. 보관 v3는 `landing2d.minimal.config(root,'v3')`로 구성할 수 있다.
- 새 체크포인트·평가는 **results/minimal_v31/**. 이전 체크포인트를 새 인코더로 해석하거나 덮어쓰지 않는다.
- `run.m`: 시드 271–275, 세 train=true로 설정. 사용자가 F5로 학습·평가한다.
- `run_check`: 전체 인코더·실제 PPO 기울기, query에 따른 순위 역전, 품질→두 번째 집계 경로, 정보·파라미터·시드·체크포인트 계약과 1 update smoke.

학습 전 구조 시험은 TEST ONLY이며 성능 개선의 증거가 아니다. 본 학습 후 OOD 성능이 PPO보다 낫지 않으면 성공했다고 기록하지 않는다.

## 6. 실행한 검증
