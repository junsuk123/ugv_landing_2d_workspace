# 일반화·강인성 개선 목표 (2026-10-25)

**목표 종료(2026-10-26, 미달성):** 사용자 결정으로 목표를 종료했다. 7개 후보와 평가 프로토콜 v1·v2 어디에서도 개발 기준을 통과하지 못했고, 확인은 한 번도 열지 않았다. 종합 결과·진단·논문 주장 범위는 [목표 종료 문서](GENERALIZATION_GOAL_CLOSURE_KO.md)에 있다. 아래는 실험별 시간순 기록이다.

사용자의 “목표 만들어서 그거 해결할 때까지 수정해줘” 지시로 목표를 생성했다. 필요한 구현·학습·평가를 반복하되, 실패를 보존하고 실제 검증이 끝나야 목표를 완료한다. 이전 v3.1 한 번의 실행 허가 이후에 주어진 최신 지시이므로 이 목표의 본 학습마다 같은 허가를 다시 요구하지 않는다.

## 목표와 완료 판정

같은 2D 물리·센서·관측·보상·행동·종료·PPO 손실과 단순한 온톨로지/R-GAT/PPO 틀을 유지한다. 귀납적 편향은 입력 배치·정보 경로·파라미터 공유로 구현한다. 방법별 파라미터 수와 학습 조건을 맞추고 PPO/TOSM/Shuffled 세 비교군을 유지한다.

고정된 `minimal_generalization_v1`의 가속·누락·잡음 조건과 주 지표를 유지한다. 개발에서 선택한 구조를 잠근 뒤 **미사용 학습 시드의 확인 실험**에서 다음을 검증한다.

1. 동등 가중 OOD 착륙률의 TOSM−PPO 및 TOSM−Shuffled 짝 차이의 보정 신뢰구간 하한이 모두 0보다 높다.
2. 잡음·가속 OOD 각각의 착륙률·위험 접촉·추종 오차를 함께 제시한다. 착륙률이 낮거나 위험 접촉·추종 오차가 악화되는 결과를 강인성 개선으로 채택하지 않는다. 조건별 구간도 공개하며 평균의 비악화와 통계적 비열등성을 구분한다.
3. 실패 시드를 포함한 전체 결과, 서명·해시, 유한 수치, 재현 스크립트와 구조/기울기 검사를 갖춘다.

개발 결과만으로 목표를 완료하지 않는다. 미지 환경 결과로 체크포인트·사건 시점·임계값을 선택하지 않는다. 확인 시험의 반복으로 우연한 양성 결과를 고르지 않도록 확인 회차 j의 유의수준 예산을 `0.05 / 2^j`로 배분하고, 두 주 비교에 다시 Bonferroni 보정한다. 기존 97.5% 개별 구간도 그대로 보고하되 목표 달성 판정은 이 추가 구간으로 한다. 각 확인 회차의 모델·학습 시드·미사용 평가 시드는 결과를 열기 전에 별도로 등록한다. 이미 연 확인 표본은 이후 개발 자료로만 취급한다.

## 첫 원인 분리: v3.2 후보

v3.1에서는 품질→두 번째 홉 경로와 역전파를 확인했지만 5개 중 2개 TOSM 시드가 충분히 학습되지 않았다. 현재 두 번째 홉은 원래 관측 증거 대신 첫 홉에서 다시 변환된 모든 노드를 값과 질의로 사용한다. 값의 재변환과 문맥 갱신이 함께 일어나는 구조다.

첫 후보는 **관측 증거 고정, 질의 문맥 갱신**만 변경한다. `H0=tanh(PX+bP)`를 두 번의 관계 메시지 값으로 유지하고, 도착 노드의 질의와 root 상태만 직전 홉에서 읽는다. 품질이 첫 홉의 문맥에 들어가 두 번째 홉의 선택을 바꾸는 경로는 유지한다. 새 특징·필터·정책 우회 입력·보조 손실·안전 가드·잔차 혼합을 추가하지 않는다. 371개 인코더/1,419개 전체 파라미터와 같은 초기 가중치를 유지한다.

이는 학습 안정성을 높일 수 있다는 가설이며 아직 성능 개선으로 판정하지 않는다. 우선 기존 개발 시드 271–275에서 두 그래프 방법을 같은 예산으로 학습해 v3.1과 짝지어 원인을 분리한다. 같은 시드의 PPO는 실제 경로와 설정이 같음을 검증한 뒤 v3.1 체크포인트를 재사용할 수 있다. 이 재사용·개발 비교는 확인 근거가 아니다.

개발 단계에서는 validation의 학습 성공·AUC·실패와 기울기를 먼저 본다. 후보를 잠그기 전 확인 표본은 열지 않는다. 새로운 개발 표본은 291–295, 첫 확인 학습 표본은 301–310을 예약한다. 기존 281–290은 v3.1의 미사용 예약으로 보존한다. 추가 후보와 확인 회차는 각각 실행 전에 등록한다.

### v3.2의 사전 고정 개발 게이트

시드 271–275의 두 그래프 비교군을 모두 끝까지 학습한다(공통 validation 조기 종료는 유지). 후보 학습 전에 다음 게이트를 고정한다.

1. 전체 미분·PPO 미분·공통 조건·1 update smoke·저장/재생 검사가 통과하고, 이전 v3.1 출력과 기울기가 비트 단위로 재현된다.
2. **두 그래프 방법 각각** 5개 중 최소 4개에서 validation 착륙률 80%에 도달하고, 선택된 체크포인트의 validation 착륙률도 최소 4개에서 80% 이상이다. 실패 시드는 제외하지 않는다.
3. TOSM의 평균 validation 학습 AUC가 같은 5시드의 v3.1 값보다 낮지 않다.

이 게이트는 학습 붕괴를 줄였는지 확인하는 개발 기준이다. PPO 대비 일반화 개선의 증거가 아니다. 통과하면 새 개발 시드 291–295의 세 방법을 학습하고 고정된 개발 일반화 평가를 진행한다. 실패하면 확인 표본을 열지 않고 원인을 다시 분석한다. 시드 271–275의 v3.2 OOD 결과는 이 게이트의 선택에 사용하지 않는다.

v3.2 식은 다음과 같다. \(H^0=\tanh(PX+b_P)\), 두 홉 \(\ell=1,2\)에서

\[
m_{j,r}=W_r H_j^0,\quad q_{i,r}^{\ell}=W_rH_i^{\ell-1},\qquad
e_{ij}^{r,\ell}=a_s^T\operatorname{LeakyReLU}(m_{j,r}+q_{i,r}^{\ell}+b_a)+\beta_r,
\]
\[
\alpha_{ij}^{r,\ell}=\operatorname{softmax}_{(j,r,i)\in E}(e_{ij}^{r,\ell}),\qquad
H_i^{\ell}=\tanh\!\left(W_0H_i^{\ell-1}+\sum_{(j,r,i)\in E}\alpha_{ij}^{r,\ell}m_{j,r}+b\right),
\quad g=H_{\mathrm{RelativeState}}^2.
\]

같은 \(W_r\)가 출발 증거와 도착 질의를 사영하고 두 홉에서도 공유된다. 학습 시 두 홉의 증거 경로와 질의 경로의 기울기를 모두 \(H^0\)와 공유 파라미터에 합친다. `config(root,'v32')`가 후보를 선택하며 기본 `v31`은 재현을 위해 유지한다.

## v3.2 완료 결과와 판정 (2026-10-25)

짝 개발 271–275의 두 그래프 방법은 모두 Reached80 5/5, 선택 검증 80% 이상 5/5였다. TOSM 평균 AUC는 같은 시드의 v3.1 0.395900에서 0.745633으로 증가해 원래 게이트를 통과했다. 소스 190개와 재사용 PPO를 포함한 15개 체크포인트를 검산했다. 이 단계의 v3.2 OOD 결과는 선택에 사용하지 않았다.

## v3.3 후보: 같은 초기 함수에서 관계별 공유 효과 분리

v3.2의 TOSM과 Shuffled는 초기 파라미터 배열이 같아도 관계 배치 때문에 초기 정책과 Critic 출력이 다르다. 고정 validation 입력 44개와 개발 시드 271–275·291–295에서 이를 확인했다. 별도의 시험용 복사본에서 아래 초기화를 적용하면 두 출력이 비트 단위로 같고, 동일 손실·head 기울기에서도 관계별 기울기 배분과 한 번의 공통 Adam 갱신 이후 출력은 달라졌다. `results/goal_generalization_20261025/TEST_ONLY_initialization_control*`은 이 구조 검사의 자료이며 성능 자료나 귀납적 편향 점수가 아니다.

후보는 초기화만 바꾼다. 기존과 같은 순서로 독립 난수 행렬 \(U_1,U_2\)를 생성한 뒤

\[
W_{\mathrm{qualifies}}^{(0)}=W_{\mathrm{informs}}^{(0)}
=\frac{U_1+U_2}{\sqrt{2}},\qquad (U_r)_{ij}\sim\mathcal N(0,1/8).
\]

각 행렬 원소의 주변 분산은 기존 fan-in 초기화와 같지만, 두 의미 행렬 사이의 초기 상관은 달라진다. 전체 초기 정책 분포가 v3.2와 같다는 주장은 하지 않는다. 두 의미 행렬은 **초기값만 같고 별개 파라미터로 학습**한다. self 행렬·root·사영·attention·head의 초기값과 난수 소비 순서, 모든 순전파·역전파 식, 371개 인코더/1,419개 전체 파라미터를 유지한다. Actor와 Critic은 각각 자신의 난수 행렬을 사용한다. 고정 물리 게이트·항등 경로·정책 우회 입력·보조 손실을 추가하지 않는다.

이는 초기 함수 차이와 관계별 공유를 분리하는 후보이지, 시드 294의 실패 원인을 이미 인과적으로 확정한 해결책은 아니다. 학습 안정성과 OOD 성능 개선은 새 실험으로 검증한다. `config(root,'v33')`만 새 초기화를 선택하며, 기본 v3.1과 기존 버전의 초기값·출력·미분은 보존한다.

### v3.3 본 학습 전 고정 게이트

1. v3.1·v3.2의 총 30개 기존 모델 출력·초기 에이전트와 20개 인코더 미분을 비트 단위로 재현한다. 새 구조·수치 미분·실제 PPO 기울기·1 update·저장/재생 검사와 공통 경로 회귀를 통과해야 한다. 두 그래프 방법의 초기 정책·Critic 함수가 같아야 한다.
2. 짝 개발은 291–295의 두 그래프 방법 10개를 같은 750×6 예산으로 새로 학습한다. PPO는 전체 공통 계약과 실제 1 update 결과가 같음을 확인한 뒤 원래 v3.2의 5개 체크포인트·서명 그대로 재사용한다. 체크포인트를 새 서명으로 바꾸지 않는다.
3. **두 그래프 방법 각각** Reached80 5/5 및 선택 검증 착륙률 80% 이상 5/5를 요구한다. v3.2의 4/5로는 한 시드의 학습 실패가 남았으므로, 이 후보의 안정성 게이트를 본 학습 전에 강화한다. TOSM 평균 AUC도 같은 시드 v3.2의 0.5851333333보다 낮지 않아야 한다. 실패 시드를 제거하거나 상한을 늘리지 않는다.
4. 이 게이트를 통과하면 미사용 개발 311–315의 세 방법 15개를 모두 학습하고 같은 9,000개 고정 개발 평가를 한다. 다음 단계 진입은 위의 두 양의 주 평균 차이와 motion·noise 세 평균의 PPO 대비 비악화 규칙을 그대로 적용한다.

**사후 기술 분석(판정 미사용):** v4·v5 개발 자료 모두에서 PPO의 OOD 착륙률이 95–97%다. 확인 규칙(시드 10개, 개별 99.1667% 하한 > 0)에 관측된 분산을 적용하면, v5 시드 기준 TOSM이 모든 OOD 에피소드에 성공해도 TOSM−PPO 필요 차이 3.37%p가 최대 가능 차이 2.73%p보다 크다. v4 시드 기준은 각각 5.75%p와 4.60%p다. v1–v5 관계 구조 변경이 모두 같은 지점에서 실패한 것은 구조만의 문제가 아니라 평가 설계의 천장과 검정력 문제일 가능성이 있다. 근거는 `results/goal_generalization_20261025/residual_ceiling_power_review.json`이다. 확인 시드의 분산은 다를 수 있어 불가능 증명은 아니다.

평가 조건·주 지표·확인 시드 수는 이 목표의 고정 계약이다. 따라서 v6 구조 후보를 바로 진행하지 않고 다음 중 사용자 결정을 기다린다. (1) 현재 계약을 유지하고 구조 후보를 계속 시도한다. (2) PPO 결과만으로 난이도를 보정한 더 어려운 OOD·더 많은 확인 시드로 평가 계약을 새로 등록한다. (3) 현재까지의 부정 결과로 목표를 종료하고 논문 해석을 정리한다. 이미 연 개발 자료로 TOSM에 유리한 조건을 고르지 않는다. 목표는 계속 진행 중이다.
