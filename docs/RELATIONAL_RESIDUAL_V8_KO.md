# 일반화 목표 재개 — 후보 C3: 관계 의미 연산자 (relational_residual_v8, 2026-10-27)

## 위치와 판단 주체

[C1](RELATIONAL_RESIDUAL_V6_KO.md)과 [C2](RELATIONAL_RESIDUAL_V7_KO.md)는 개발 기준을 통과하지 못했다. 그래서 Codex 계획의 등록 예산은 소진됐다. 이후 2026-10-27 사용자가 두 가지를 지시했다.
- "코덱스 한도 복원되기 전까지 너가 판단해서 수정해줘"
- "참고로 관계를 셔플 하면 잘 안되는게 맞아"

Codex가 사용량 한도로 2026-11-02 15:35까지 쓸 수 없어서, 그동안 Claude가 판정자 역할을 맡는다. 판정 규칙은 그대로 유지한다. 개발과 확인을 분리하고, 기준은 학습 전에 고정하며, 실패 시드를 제외하지 않고, 결과를 본 뒤 기준을 완화하지 않는다. 목표와 완료 판정은 [목표 문서](GENERALIZATION_GOAL_KO.md)와 같다. 달성은 보장되지 않는다.

## 근거

v1–v7의 진단과 결과에서 다음을 확인했다.
- **관계 유형이 계산을 바꾸지 않았다.** 모든 잔차 버전에서 관계 연산은 같은 가산 메시지(`message`)였다. 관계 유형은 어떤 가중치를 공유하느냐만 정했다. 그래서 Shuffled도 같은 함수를 다시 학습할 수 있었다. 실제로 관계 타입을 교환했을 때 행동 변화는 0.006 m/s²에 그쳤다([귀납 편향 진단](INDUCTIVE_BIAS_DIAGNOSTICS_KO.md)). TOSM−Shuffled는 후보마다 부호가 바뀌었다.
- **readout이 우회로였다.** 네 노드 전체를 읽는 readout 때문에 목표 운동 같은 노드 정보가 관계 간선을 거치지 않고 행동에 닿았다.
- **보정 경로가 거의 학습되지 않았다.** σ(β)가 초기값 0.12 근처(학습 후 0.135)에 머물러, 보정 경로의 출력 변화 속도가 기본 MLP의 약 1/8이었다.

사용자 지적대로 관계를 잘못 배치하면 성능이 떨어져야 한다면, 관계 유형이 실제 계산 의미를 가져야 한다. C3는 이 점을 직접 시험한다. 이 설계가 OOD 우위를 낸다고 미리 가정하지 않는다.

## 변경 (v5 기반, tanh, C1 φ·C2 폭과 결합하지 않음)

**1. 관계별 연산자 (`correctionOperators = 'semantic_v1'`)**

[semanticGraphForward](../src/algorithms/+landing2d/+residual_context/semanticGraphForward.m)에서 간선의 관계 유형이 연산자를 정한다.

| 관계 | 연산 |
|---|---|
| qualifiesEstimate (품질 → 추정) | 도착 노드 표현을 곱셈으로 조절한다. G_i = Π(1 + tanh(W_q h_j + b_q)) ∈ (0,2)이고, 해당 간선이 없으면 1이다. |
| informsMotion (운동 정보) | attention 가중 가산 메시지 W_r h_j. 메시지 합은 tanh를 거치지 않고 들어간다. |
| self | 가산 메시지 W_s h_i. root는 tanh(W0 h_i + b)다. |

- 노드 갱신은 h_i ← G_i ⊙ (tanh(W0 h_i + b) + Σ α W h_j)이고, 두 홉 동안 파라미터를 공유한다. 메시지와 query는 현재 표현에서 나온다.
- attention은 v5의 동적 joint attention이며, 도착 노드로 들어오는 가산 간선(informsMotion, self) 위에서 계산한다.
- 노드 증거 H0 = tanh(P_i u_i + bp_i), 관측 좌표 `masked_own_vx_v1`, 4노드 10간선 위상은 v5와 같다.

**2. 목표 노드 readout**

그래프 보정은 RelativeState 노드 표현만 읽는다(R은 2×8). 그래서 모든 그래프 입력이 유형이 붙은 간선을 거쳐야 행동에 닿는다.

**3. 혼합 초기값**

세 잔차 방법 모두 β = 0(σ = 0.5)에서 시작한다(v5는 −2). R = 0은 유지하므로 초기 정책은 base와 같다.

**4. 파라미터 수 맞춤**

세 잔차 방법의 기본 MLP 폭은 77, Residual-MLP 보정 폭은 32다.

| 방법 | 구성 | 합계 |
|---|---|---|
| PPO | v5와 같음 (10→110→2, Critic 10→55→1) | 2,095 |
| Residual-MLP | 13·77+2 = 1003, 13·32+3 = 419, Critic 661, logσ 2 | 2,085 |
| TOSM·Shuffled | 1003, 그래프 421 (P 80, bp 32, W 192, a 18, b_q 8, W0 64, b 8, R 16, br 2, β 1), 663 | 2,087 |

최대 차이는 0.48%다.

**공정성**
- TOSM과 Shuffled는 같은 난수로 같은 파라미터를 뽑고, 같은 연산자 집합을 쓴다(게이트 2, 가산 의미 간선 4, self 4).
- Shuffled는 v5 규칙(graphSeed = trainSeed, 의미 간선 6개 중 4개 유형 교란, 유형 수와 self 보존)으로 연산자를 다른 간선에 옮긴다. 결과를 보고 배치를 고르지 않는다.
  - 모든 Shuffled 배치에서 Q→R과 Q→T는 가산 메시지가 된다.
  - 시드별로 운동 간선 두 개가 게이트가 된다. 471·472는 U→R·R→T, 473은 R→T·R→U, 474는 T→R·U→R, 475는 T→R·R→U다.
- 연산자를 관계 유형에 묶는 것은 이 연구가 주장하는 온톨로지 귀납 편향의 내용 그 자체다. 따라서 이번에는 "Shuffled만 불리한 연산 금지"를 "같은 연산자 집합을 쓰고 배치만 바꾼다"로 해석한다.
- 이 해석은 C1에서 Codex가 둔 관계 대칭 조건과 다르다. Codex가 돌아오면 검토받는다.
- 초기 함수는 TOSM과 Shuffled가 다르다. 배치가 계산을 바꾸기 때문이다.

**바뀌지 않는 것:** PPO, 공통 raw Critic, 관측, 물리, 센서, reward_v5, 행동, 종료, PPO 손실, 학습 분포(a2 0.3–0.8), 학습률, 탐색, 750×6 상한, validation 규칙.

**예상 실패 양상**
- 목표 노드 readout과 게이트 때문에 학습이 느려지거나 실패할 수 있다.
- β = 0 때문에 초기 학습이 불안정해질 수 있다.
- 잘못 배치한 Shuffled가 학습에 실패해 TOSM−Shuffled가 과장될 수 있다. 이 경우 일반화 효과로 해석하지 않는다.
- 학습된 모델 사이의 OOD 차이가 여전히 작을 수 있다.
- 잡음 OOD에서 가산 경로가 잡음을 증폭할 수 있다.

## 개발 (프로토콜 v2)

- 471–475 × 네 방법, 모두 새로 학습한다. 시드 미사용 감사 결과 CSV 703개와 체크포인트 352개에서 사용 0건이었다.
- 평가: 가속 1.5–2.0 m/s², 누락 2.1–2.9 s, 잡음 ×3, 환경 9001–9100에서 12,000회.
- 개발 기준은 C1·C2와 같은 v5 규칙(`landing2d.residual_soft.developmentGate`)이다.
  - 네 방법 모두 학습 5/5
  - TOSM validation·위험 중앙값 조건
  - 세 OOD 평균 차이가 모두 양수
  - motion·noise 평균 방향
- 기준을 바꾸지 않는다. 98.3333% 구간은 보고만 한다.

## 확인 (개발 통과 시에만, 별도 등록 뒤)

C1 계획과 같다.
- 431–450 × 네 방법을 새로 학습한다.
- 환경 9101–9200에서 48,000회 평가한다.
- 확인 회차 j = 1, alpha = 0.025, 세 비교 Bonferroni, 99.1667% 짝 t 구간(df = 19)을 쓴다.
- TOSM−PPO와 TOSM−Shuffled 하한이 모두 0보다 크고, motion·noise 비악화와 전체 검산을 충족해야 한다. 실패 시드를 포함한 20쌍 전체를 쓴다.
