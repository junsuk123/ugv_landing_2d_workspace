# 후속 코드 수정 가이드

## 프로젝트 범위

UGV 패드 추종, 2차원 x-z 운동, FOV 상실 시 상승, 재포착 후 착륙만 다룹니다.
제어기는 세 종류이며, **모두 수평/수직 가속도 명령을 출력**합니다.

1. 기준 비례 항법(PN) 유도
2. PN 유도를 교사로 모방 학습한 뒤 PPO로 미세조정한 강화학습 제어기 (보상 가중치는 손으로 지정)
3. 보상 가중치를 온톨로지 기반 R-GAT로 추론하고, 모방 학습 없이 처음부터 학습한 제어기 (제안 모델)

기존 PD 제어기는 `controller='pd'` 경로로만 남아 있습니다. 원본 단일 파일과의 회귀 비교 전용입니다.

사용자 요청 없이 EKF, 6자유도 모델, 실제 비행 스택 연동을 추가하지 않습니다.
강화학습은 `+rl`, 온톨로지/R-GAT는 `+ontology`와 `+rgat` 안에서만 구현하며 별도 Toolbox를 쓰지 않습니다.

## 진입점과 경로

| 실행 | 내용 |
|---|---|
| `run_all.m` | **통합 진입점**. 세 비교군의 전체 시나리오와 학습을 모두 수행 |
| `run_ugv_landing_2d.m` | 기준 유도 법칙 단독 실행 (실시간 애니메이션 포함) |

기본 설정은 `src/+landing2d/+config/defaultConfig.m`,
학습 설정은 `+rl/defaultRlConfig.m`, 온톨로지 설정은 `+ontology/defaultOntologyConfig.m`입니다.
`setup_project`를 통해 루트와 src만 MATLAB 경로에 추가합니다. 개별 +패키지 디렉터리를 경로에 직접 넣지 않습니다.
`tests/reference`는 회귀 비교 전용입니다. 여기에 있는 원본 파일을 수정하거나 정상 실행에 사용하지 않습니다.

## 유지할 조건

- 시각화 수정만 요청된 경우 `control`, `dynamics`, `scenario`의 수치 계산을 바꾸지 않습니다.
- PD 경로(`controller='pd'`) 결과는 `test_baseline_equivalence`가 고정합니다.
  유도 법칙을 바꾸거나 비교군을 추가한다고 이 경로의 수치를 바꾸지 않습니다.
  `pdController.m`은 상태기계 사본까지 그대로 둡니다. 공용 `control.trackingMode`로 바꾸지 마세요.
- 제어기를 추가하면 `control.command`에 등록하고, 출력은 반드시 가속도 [m/s^2]로 맞춥니다.
  속도나 자세 명령을 내보내면 세 비교군의 명령 차원이 달라져 비교가 성립하지 않습니다.
- 유도 이득을 바꾸면 교사 시연이 바뀌므로 저장된 정책과 보상 설계가 모두 무효가 됩니다.
  `trainingSignature`와 `designSignature`에 유도 설정이 들어 있으니 빼지 마세요.
- 패드가 비가시 상태일 때 실제 현재 패드 위치/속도를 제어기 입력에 넣지 않습니다. 정책 관측도 같은 규칙을 따릅니다.
- 접촉 판정, 보상 계산, 온톨로지 의미 채널, 평가 로그에서만 환경 참값을 사용합니다.
  온톨로지 그래프는 학습 전 가중치 설계에만 쓰고 정책 입력으로 넘기지 않습니다.
- 강화학습 rollout은 `sensing`, `environment`, `dynamics`의 같은 함수를 호출합니다. 비교를 위해 환경을 복제하지 않습니다.
- 보상 항은 두 개(패드 포착, 착륙 지점 거리)로 유지합니다. 온톨로지 R-GAT는 이 두 항의 **가중치만** 결정합니다.
  항을 늘리거나 형태를 바꾸려면 사용자에게 먼저 확인합니다.
- 온톨로지 비교군은 기준 유도 법칙의 모방 학습으로 초기화하지 않습니다(`applyDesign`이 `useBehaviorClone=false`).
  결과가 보상 설계에서 나왔다고 말하려면 이 조건이 필요합니다. 학습을 빠르게 하려고 되돌리지 마세요.
- 그 대신 이 비교군은 학습 설정(`rl.scratch`)도 다릅니다. 비교 결과를 적을 때
  "가중치만 다르다"고 쓰지 말고, 초기화와 학습 예산도 다르다는 점을 함께 적으세요.
- 현재 설정에서 온톨로지 비교군은 첫 속도 전환(8초) 이전에 착륙해 시야 이탈 구간을 겪지 않습니다.
  교란 대처를 비교하려면 `segmentTimes(1)`이나 `initialHeight`를 먼저 바꿔야 합니다.
- 서로 다른 가중치로 학습한 정책은 서로 다른 파일에 저장합니다(`applyDesign`이 `policyFile`을 바꿉니다).
- 제어기별 평가 점수(`rl.evaluate`의 score)는 보상 가중치가 다르면 서로 비교할 수 없습니다.
  비교는 착륙 시각, 포착률, 접지 오차 같은 물리량으로 합니다.
- 그림의 구간 속도는 목표 속도입니다. 실제 가감속 곡선과 구별해서 표시합니다.
- x-z 공간 배경과 시간 구간을 같은 의미로 취급하지 않습니다.
- 생성 데이터는 results에 저장합니다. 시뮬레이션하지 않은 숫자를 결과 파일로 만들지 않습니다.
- 학습/설계 결과를 바꾸는 설정을 수정하면 `results/rl_policy*.mat`와 `results/reward_design.mat`는
  지문(`trainingSignature`, `designSignature`)이 달라져 자동으로 무효가 됩니다. 이 규칙을 우회하지 않습니다.
- 전역 그래픽 기본값, MATLAB 사용자 경로, 사용자의 다른 창을 임의로 초기화하지 않습니다.

## 온톨로지 스키마를 고칠 때

`+ontology/nodeSchema.m` 한 곳에 노드, 간선, 보상항 대응이 모여 있습니다.

- 현재 8노드는 노드별 반사실 기여도를 측정해 정한 최소 구성입니다.
  노드를 더하거나 빼려면 `landing2d.ontology.nodeImportance`로 기여도를 먼저 측정하고,
  검증 MSE와 추론 비율이 유지되는지 확인한 근거를 문서에 남기세요.
- 노드를 추가하면 `inDim`이 함께 바뀌며 저장된 설계와 R-GAT 파라미터는 재사용할 수 없습니다.
- 목표 노드 값은 항상 0입니다. 여기에 결과를 넣으면 정답이 누출됩니다.
- 보상항에 대응하는 노드 묶음은 서로 겹치면 안 됩니다. 반사실 민감도의 의미가 사라집니다.
- 위험 노드 -> 중간 노드 -> 목표 노드의 2단 구조와 네 종류 관계는 유지합니다.
  둘 중 하나가 무너지면 그래프 신경망을 쓸 이유가 사라집니다.
- 스키마를 바꾸면 `test_ontology_schema`가 먼저 실패합니다. 테스트를 고치기 전에 의도가 맞는지 확인합니다.
- 증류 결과는 `designRepeats`번 학습의 평균입니다. 1회로 줄이면 비율이 난수에 따라 흔들립니다.

## 검증

`run_tests(false)`는 원본 수치 결과 비교(PD 경로), 비례 항법 유도, 비가시 정보경계,
UGV 속도 구간, 옵션 검증, 강화학습 역전파/관측/파이프라인, R-GAT 역전파,
온톨로지 스키마, 가중치 증류를 확인합니다.
`run_tests`는 이에 더해 반투명 배경 및 PNG/FIG 저장을 확인합니다.
실제 MATLAB에서 테스트하지 않은 경우 테스트 통과 또는 GUI 검증 완료라고 기록하지 않습니다.
